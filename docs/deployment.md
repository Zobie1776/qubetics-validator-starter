# Deployment Guide

This guide covers deploying the Qubetics validator stack across bare metal, Docker, and infrastructure-as-code options.

## Prerequisites

- Ubuntu 20.04/22.04 LTS with sudo access
- 8+ vCPUs, 32GB RAM, 1TB NVMe SSD
- Static public IP, reverse DNS, and firewall control
- Backup storage for validator keys and snapshots

## Bare metal workflow

1. Copy `config.sample.env` to `.env` and populate environment variables (chain ID, ports, domain, alerting tokens).
2. Run `make setup MONIKER=<your-moniker>` as root.
3. Import validator keys offline, then place them into `$HOME_DIR/config`.
4. Run `make finish` once the node has fully synced and is funded.
5. Schedule `make snapshot` and `make backup` through cron (example provided in `docs/monitoring.md`).

## Docker workflow

```bash
cp config.sample.env .env
make docker-up
docker compose -f docker/docker-compose.single.yml logs -f
```

Override ports and tags using environment variables (see `config.sample.env`). Use `docker/docker-compose.ha.yml` for validator+sentry+metrics deployments.

## Infrastructure as code

- `infra/terraform` provisions an AWS EC2 instance with hardened security groups, user-data bootstrap, and metrics exposure.
- `infra/ansible/playbook.yml` installs Docker and brings up the HA Compose stack on existing hosts.

## High availability

1. Deploy validator behind at least two sentry nodes using the HA Compose file.
2. Use private networking (WireGuard/VPC peering) between validator and sentries.
3. Expose Prometheus metrics on private networks only; scrape via a dedicated monitoring VPC.

## Disaster recovery

- Store encrypted backups generated by `make backup` off-site.
- Keep at least 3 recent snapshots from `make snapshot` and validate them weekly with `make snapshot-restore` on a test host.
- Document operator runbooks in your organization’s wiki and link them in `docs/faq.md`.
